# T212 Rate Limit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop Trading 212 HTTP 429s by ranking on Yahoo/LLM as today, placing orders without per-fill cash GETs, retrying 429 once, and reconciling the book only at session end.

**Architecture:** `broker._request` retries HTTP 429 after 5s once. `_refresh_cash` during fills is local-only. `run_session` sleeps 2s between order POSTs. `__main__` still aborts if the start snapshot fails; a failed end snapshot logs and still saves the local book. `get_open_positions` returns `None` on transport/HTTP failure so a 429 cannot be mistaken for an empty portfolio.

**Tech Stack:** Python 3.11, httpx, unittest.

## Global Constraints

- Do not call `GET /equity/account/cash` during fills.
- Sleep 2.0s between order POSTs.
- HTTP 429: log `BROKER_429 {method} {path}`, sleep 5s, retry once, then `None`.
- Start snapshot failure exits; end snapshot failure does not.
- £10k cap, news gate, MAX_POSITIONS=10 unchanged.
